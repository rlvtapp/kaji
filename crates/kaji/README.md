# Kaji

`kaji` is the first-party Rust composition layer for SDK
generation. It turns selected language/transport targets into isolated,
publishable packages while `kaji-core` owns the neutral AST and plugin
engine.

```rust
use kaji::{ProfileSet, TypeScriptOptions, generate};

let profiles = ProfileSet::new("sdks")
    .rust()
    .typescript_fetch()
    .typescript_axios()
    .go()
    .python()
    .php()
    .java()
    .dotnet()
    .elixir()
    .mock_server()
    .typescript_options(TypeScriptOptions::default());
let tree = generate(&api, profiles)?;
```

Native language packages default to a resource-namespaced facade. Configure a
particular package as a conventional flat client when that fits an existing
codebase better:

```rust
use kaji::PackageOptions;

let profiles = ProfileSet::new("sdks")
    .go_options(PackageOptions::flat())
    .go();
```

The current target set is Rust/Reqwest, TypeScript/Fetch, TypeScript/Axios,
Go, Python, PHP, Java, .NET, and Elixir. TypeScript packages use a structured directory layout
and client surface generated by the Rust-native implementation. Their default
surface is a namespaced instantiated client, such as
`new KajiEmail({ apiKey }).contacts.create(...)`; direct function exports
remain available for lower-level use.

## Standalone contract mocks

`ProfileSet::mock_server()` emits one language-neutral mock package alongside
the selected SDKs. It contains deterministic `httpmock` YAML fixtures, a
Dockerfile, `compose.yaml`, and a small runner:

```rust
use kaji::{MockServerOptions, ProfileSet, generate};

let tree = generate(&api, ProfileSet::new("release")
    .typescript_fetch()
    .rust()
    .mock_server()
    .mock_server_options(MockServerOptions {
        image: "httpmock/httpmock".into(),
        port: 5000,
    }))?;
```

Materialize the resulting `release/mock-server` directory, then run
`docker compose up --build` (or `sh ./run.sh`). Every language SDK can point
its base URL at `http://localhost:5000`; no Node or SDK-specific mock runtime
is involved. Put durable failure and conditional-response behaviour in the
OpenAPI document's `x-kaji-mock` extensions so fixtures regenerate from the
same contract as docs and SDKs.
